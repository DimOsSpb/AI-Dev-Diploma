# Блок 5.4 — Chunking и оптимизация качества

## Что делаем
Продолжаем RAG, собранный в ДЗ Б5.3 (`Document` → `SentenceSplitter` → `Qdrant` → `QueryEngine`). На этот раз интуиция заменяется измерениями: готовится golden dataset из 20+ вопросов, прогоняются три стратегии chunking (fixed-size, recursive, semantic), считаются `Hit Rate@5`, `MRR@10`, `Recall@10`, добавляется re-ranker и подбираются (`chunk_size`, `overlap`, `top-K`) по числам.

## Задачи

1. **Подготовить golden dataset** на 20+ вопросах из предметной области: для каждого вопроса вручную выписать 1–3 релевантных документа (`id` или путь в `data/`). Положить в `tests/eval/retrieval_dataset.json` со схемой полей `question`, `relevant_doc_ids`. Вопросы должны покрывать разные сценарии — точечные факты, сравнения, многошаговые ответы.
2. **Реализовать три стратегии chunking** как функции в `app/services/chunking.py`:
   * `fixed_size`: `TokenTextSplitter` с `chunk_size=512`, `chunk_overlap=64` (baseline; режет по токенам без учёта границ предложений).
   * `recursive`: `SentenceSplitter` с настройкой через `paragraph_separator="\n\n"` и `chunking_tokenizer_fn` под русские предложения — это эквивалент LangChain `RecursiveCharacterTextSplitter`. Не путать с `HierarchicalNodeParser` — это другой подход (3-уровневый сплиттер 2048/512/128 для `AutoMergingRetriever`), у него своя ниша, в этом эксперименте не используется.
   * `semantic`: `SemanticSplitterNodeParser` (`buffer_size=1`, `breakpoint_percentile_threshold=95`, `embed_model` тот же, что и в индексе).
3. **Переиндексировать коллекцию** в Qdrant для каждой стратегии с уникальным именем (`docs_fixed`, `docs_recursive`, `docs_semantic`). Записать среднее число чанков на документ, общее число чанков и среднюю длину чанка в `docs/chunking_experiment.md`.
4. **Реализовать метрики retrieval** в `app/services/retrieval_eval.py`: `Hit Rate@5`, `MRR@10`, `Recall@10`. Метрики считаются по golden dataset из шага 1, единая функция-обёртка должна возвращать словарь со всеми тремя числами.
5. **Прогнать каждую стратегию** на golden dataset, сохранить результаты в таблицу `docs/chunking_experiment.md`. Обязательные колонки: стратегия, `Hit Rate@5`, `MRR@10`, `Recall@10`, средняя длина chunk, скорость retrieval (мс).
6. **Добавить re-ranker**: один из вариантов — Cohere Rerank (`rerank-v3.5`) или open-source cross-encoder (`BAAI/bge-reranker-v2-m3` через `sentence-transformers`). Обернуть в `app/services/reranker.py` (вход — список кандидатов, выход — пересортированный top-N). Перепрогнать метрики на лучшей стратегии с re-ranker и без — добавить две новые строки в таблицу.
7. **Подобрать (`chunk_size`, `overlap`, `top-K`)** для лучшей стратегии: минимум 4 эксперимента (например, chunk_size 256/512, overlap 32/64, при фиксированном `top-K=10` и `top-K=20`). Записать итоговую конфигурацию в `app/config.py` (или `.env`).

## Критерии самопроверки

* [ ] `tests/eval/retrieval_dataset.json` содержит ≥ 20 вопросов, для каждого — 1–3 эталонных документа.
* [ ] Все три стратегии chunking реализованы и проиндексированы в отдельные коллекции Qdrant (`docs_fixed`, `docs_recursive`, `docs_semantic`).
* [ ] `docs/chunking_experiment.md` содержит итоговую таблицу с числами для всех трёх стратегий + строки до/после re-ranker.
* [ ] Re-ranker (Cohere Rerank или `bge-reranker-v2-m3`) подключён, метрики измерены до/после.
* [ ] Лучшая конфигурация (`chunk_size`, `overlap`, `top-K`) зафиксирована в `app/config.py` (или `.env`).
* [ ] Финальный `Hit Rate@5` ≥ 0.5 на golden dataset (на дипломных корпусах 10+ документов 0.6 часто не достижим без hybrid/rerank). Если ниже — в `docs/chunking_experiment.md` записан анализ причин и план следующей итерации.
* [ ] В `docs/chunking_experiment.md` есть итоговый параграф «выбираю стратегию X с конфигом Y, потому что …» с опорой на числа из таблицы.
